# 깊은 곳 · Deepdelve

15층 아래로 내려가는 도트 로그라이크. **이미지 파일이 한 장도 없습니다** — 스프라이트는 전부 `src/pixels.js` 안의 문자열 격자이고, 벽과 바닥은 좌표 해시로 생성됩니다. 엔진도, 빌드 단계도, 의존성도 없습니다.

Moria의 *구조*를 이어받았습니다: 여덟 종족 × 여섯 직업, 여섯 능력치, 상점 여섯 개가 있는 마을(0층), 깊이로 통제되는 몬스터 테이블, 밝은 방과 어두운 복도, 식량과 횃불 시계.

## 배포

```bash
git init && git add . && git commit -m "Deepdelve v1"
git remote add origin git@github.com:<you>/deepdelve.git
git push -u origin main
```

Settings → Pages → Source `main` / `/ (root)`. 폰 브라우저에서 열고 **홈 화면에 추가**하면 전체화면 PWA로 실행되고, 서비스 워커가 붙어 오프라인에서도 돌아갑니다.

로컬 확인은 `python3 -m http.server 8080`. ES 모듈이라 `file://`로는 열리지 않습니다.

서비스 워커는 **네트워크 우선**입니다. 예전엔 캐시 우선이라 한 번 방문한 사람이 갱신을 한참 뒤에야 봤는데, 지금은 온라인이면 항상 최신을 받고 캐시는 오프라인 대비로만 씁니다. 새 워커가 설치되면 페이지가 스스로 한 번 새로고침합니다. 타이틀 화면 아래의 `v6`가 빌드 표시입니다.

## 구조

```
index.html      화면 8개의 마크업 (타이틀·생성·플레이·배낭·상점·주문·도움말·결말)
styles.css      16색 팔레트 기반 UI
src/pixels.js   팔레트, 스프라이트 격자 37종, 절차적 벽/바닥 생성기
src/data.js     종족·직업·주문·몬스터·아이템·상점·상태이상·함정 테이블
src/world.js    마을/던전 생성, 특수 타일, 그림자 캐스팅 시야
src/game.js     상태, 턴, 전투, 인벤토리, 상점, 주문
src/juice.js    타격 연출 — 파편, 데미지 숫자, 흔들림, 히트스톱
src/save.js     슬롯 3개 직렬화 (localStorage)
src/ui.js       캔버스 렌더링, 화면 전환, 입력
```

**렌더링은 `ui.js`에만 있고 규칙은 `game.js`에만 있습니다.** 이 경계 덕분에 헤드리스 시뮬레이션이 가능합니다 (아래 참고).

`juice.js`도 이 경계를 지킵니다. `game.js`는 무슨 일이 일어났는지만 `G.fx` 큐에 밀어 넣고 (`{t:'kill', x, y, over}` 같은 서술), 그걸 얼마나 요란하게 그릴지는 `juice.js`가 정합니다. 규칙 쪽은 여전히 DOM을 모릅니다.

### 도트를 그리는 법

`src/pixels.js`에서 스프라이트는 이렇게 정의됩니다.

```js
potion: [
  '...ww...',
  '...ww...',
  '..wRRw..',
  '.wRRRRw.',
  ...
],
```

각 글자는 `PALETTE`의 색을 가리키고, `.`은 투명입니다. 부팅 시 8×8 캔버스로 한 번 구워두고 이후엔 `imageSmoothingEnabled = false`로 확대해 찍습니다. 새 몬스터를 추가하려면 격자 하나를 쓰고 `data.js`의 `MONSTERS`에 `spr` 키로 연결하면 끝입니다.

플레이어 스프라이트의 `C` 채널은 직업별 색으로 치환됩니다 (`CLASS_TINT`).

### 전투에 값 매기기

숫자만 큰 쪽이 이기는 교환이 아니라 **결정**이 되도록 세 가지 배율을 겁니다.

- **치명타** — 민첩과 레벨로 확률이 오릅니다. 도적 25%, 판금 입은 전사 9%.
- **기습** — 아직 자고 있는 적을 치면 **확정 치명타에 ×1.5**가 더 붙습니다. 12레벨 하플링 도적이 잠든 동굴 트롤에게 한 방에 56 피해를 넣습니다.
- **연격** — 연달아 처치하면 피해가 누적으로 최대 +70%. 14턴 안에 다음을 잡지 못하면 끊기고, 한 대 맞으면 절반이 날아갑니다.

기습이 실제로 성립하려면 몬스터가 즉시 깨면 안 됩니다. 그래서 **인지는 매 턴 굴리는 확률**이고, 거리와 **은신**으로 결정됩니다. 은신은 민첩·종족·직업에서 오르고 **갑옷 무게로 깎입니다**.

```
빌드                       은신   치명타   접근 성공률    AC
하플링 도적 · 가죽+작은방패    72%    25%       41%       12
하플링 도적 · 판금            54%    25%       21%       27
인간 전사 · 가죽              12%     9%        4%        9
인간 전사 · 판금+탑방패         0%     9%        2%       35
```

판금은 살려주고 복도 끝까지 소리를 냅니다. 둘 중 하나를 고르세요. 이 수치는 배낭 화면의 **전투** 칸에 그대로 표시됩니다 — 갑옷을 갈아입는 바로 그 자리에서 보입니다.

어두운 방이 유리해진 것도 이 규칙의 결과입니다. 시야에 들지 않은 몬스터는 인지 판정 자체를 굴리지 않습니다.

### 몬스터가 하는 일

20종이 전부 직진해서 무는 것 말고는 할 줄 아는 게 없었습니다. 이제 각자 다르게 움직입니다.

- **속도** — 에너지 예산입니다. 늑대 1.35, 박쥐 1.7은 당신보다 자주 움직이고, 오우거 0.75와 미라 0.65는 덜 움직입니다. **도망칠 수 있는 상대와 없는 상대가 갈립니다.**
- **원거리** — 투석꾼·궁수·거인·용·비룡·리치는 멀리서 쏩니다. 붙으면 물러나며 계속 쏘기 때문에, 시야를 끊거나 단숨에 붙는 것 외에 답이 없습니다. 시위를 메기느라 대부분 `spd 0.7` 이하입니다.
- **무리** — 코볼드·오크·늑대·들개는 떼로 스폰됩니다. 총 마릿수는 그대로지만 **뭉쳐서** 나옵니다. 넓은 방에서 둘러싸이는 것과 복도에서 한 마리씩 상대하는 것은 완전히 다른 문제입니다.
- **도주** — 들개는 피를 흘리면 달아납니다. 쫓을지 보낼지가 선택이 됩니다.
- **상태이상** — 중독·실명·공포·둔화·마비. 종족 설명문이 지금까지 약속만 해 온 것들을 실제로 구현했습니다: **노움은 마비되지 않고, 드워프는 눈이 멀지 않으며, 엘프와 하프트롤은 겁먹지 않습니다.** 엘프의 "눈이 밝다"는 시야 +1이고, 하프트롤의 "상처가 저절로 아문다"는 재생 +1입니다.
- **문** — 오크·코볼드·흡혈귀·리치는 엽니다. 오우거·트롤·거인·용은 부숩니다. **나머지는 닫힌 문 앞에서 멈춥니다.**

### 문 · 함정 · 바닥

문이 하나의 타일에서 넷이 됐습니다. 닫힌 문은 **시야를 완전히 끊습니다** — 이게 위의 원거리 몬스터와 무리 몬스터에 대한 답입니다.

문 닫기(`c`)는 곁에 열린 문이 있을 때만 버튼이 나타납니다. 추격을 끊는 가장 확실한 수단이고, 무엇이 쫓아오고 있느냐에 따라 통할 수도 안 통할 수도 있습니다.

잠긴 문은 열쇠로 열거나 힘으로 부숩니다. **부수는 소리는 11칸까지 갑니다.** 생성 후 잠긴 문을 벽으로 간주하고 입구에서 계단까지 도달 가능한지 검사해, 막혀 있으면 경로상의 자물쇠를 풀어 줍니다.

함정 다섯 가지 — 화살·독침·구덩이·전이·경보. 밟기 전에는 보이지 않고, 매 턴 주변 2칸을 지혜와 직업으로 굴려 발견합니다(도적 +0.28). 발견한 함정은 자동 이동이 알아서 피해 가되, **피할 길이 없으면 밟고 지나갑니다** — 한 칸짜리 복도의 함정 하나가 층을 반으로 갈라 버리지 않도록 2패스로 탐색합니다.

거미줄은 걸리면 힘으로 뜯어내야 하고, 거미는 그냥 지나갑니다. 얕은 물은 다치지 않지만 **은신이 1/4로 떨어집니다** — 아래의 은신 규칙과 직접 맞물립니다.

### 상자와 미믹

상자는 밟으면 열립니다. 잠긴 상자는 전리품이 두 배에 금화 1.8배지만 자물쇠를 따야 하고(도적 +0.30), 뚜껑에 함정이 걸려 있을 수 있습니다.

그리고 **상자처럼 생긴 것이 전부 상자는 아닙니다.** 미믹의 비중은 깊이에 따라 6%에서 34%까지 오릅니다. 건드리면 먼저 뭅니다.

미믹은 상자와 같은 스프라이트를 쓰지만 한 가지 티가 납니다 — **숨을 쉽니다.** 아주 느리게 위아래로 움직입니다. 급하게 내려가는 사람은 못 보고, 화면을 보고 있던 사람은 봅니다. 생명 탐지 주문은 한 번에 전부 벗겨냅니다. 능력치는 층에 맞춰 계산되므로, 1층의 상자가 10층 오우거처럼 때리는 일은 없습니다.

### 접두 · 접미 속성

하나의 어휘를 셋이 나눠 씁니다 — 장비, 주문, 몬스터. 필드는 `dmgPct` 하나만 곱연산이고 그건 의도한 것입니다. **곱해지는 자리가 말도 안 되는 빌드가 사는 곳**이기 때문입니다.

한 무기에 **연쇄의**(45%로 옆 적에게 파급) + **작열하는**(처치 시 폭발) + **갈증**(흡혈)을 모으면, 한 번 휘두를 때 두 마리가 맞고, 죽은 쪽이 터지고, 그 피해가 당신을 회복시킵니다. `data.js`의 그 세 줄은 서로의 존재를 모릅니다.

그 외에 꿰뚫는(방어 관통) · 처형(체력 22% 이하 즉사) · 예리한 · 분노 · 룬이 새겨진(상태이상 면역) · 등불의(시야 +3) · 그림자. 저주는 무딘 · 시끄러운 · 삭은 · 짐 · 부패 다섯이고 **인챈트 도박에서만** 나옵니다.

주문도 같은 모양을 씁니다 — 메아리치는(두 번째 대상에게 절반) · 강대한 · 간결한 · 흡수하는 · 거친(위력 +90%, 마나 +2).

몬스터 쪽은 **정예**입니다. 이름 앞에 접두가 붙고 주황색 고리가 돕니다. 경험치 약 두 배에, 죽으면 반드시 속성 붙은 장비를 떨어뜨립니다. 싸울지 피할지가 선택이 됩니다. 정예 판정은 **개체마다** 굴립니다 — 무리 단위로 굴렸더니 운 나쁜 한 번이 정예 검은 오크 네 마리를 동시에 만들었습니다.

### 여섯 직업, 여섯 축

직업이 능력치 수정치이면 그건 직업이 아니라 숫자입니다. 여섯 개가 서로 겹치지 않는 **규칙** 하나씩을 갖도록 정리했습니다.

| 직업 | 축 | 무엇을 묻는가 |
|---|---|---|
| 전사 | 세 번째 손 + **연타** | 한 대가 다음 대를 키운다 — 한 턴 안에서 |
| 마법사 | **잔향** | 방금 쓴 주문이 다음 주문을 바꾼다 — 순서 |
| 사제 | 응답 | 지고 있을 때 더 아문다 |
| 도적 | **그림자** | 보이지 않는 동안 모아서 한 번에 태운다 |
| 레인저 | 표적 + 화살 | 거리를 지운 쪽이 진다 |
| 팔라딘 | **맹세** | 맞아서 쌓은 벽이 곧 탄약이다 |

넷은 이번에 새로 놓았습니다.

**도적의 그림자.** 예전엔 마법사의 주문 다섯을 그대로 들고 있었고 (봇이 판당 마력 화살을 27.6번 쐈습니다), `p.shadow`는 0/1 램프라 모을 수도 아낄 수도 없었습니다. 지금은 0에서 5까지 차는 탄약입니다 — 모르는 것을 찌르거나, 구르거나, 들키지 않은 채 다섯 턴을 보내면 하나씩. 태우는 곳은 기예 넷뿐입니다.

넷 중 **둘은 반드시 무리와 원거리에 대한 답**이어야 했습니다. "안 들키면 세고 들키면 맨몸"은 궁수와 무리 앞에서 그냥 죽는 직업이니까요. **그림자 도약**은 보이는 적 등 뒤로 건너뛰어 궁수가 이기는 방법인 거리를 지우고, **칼부채**는 앞의 부채꼴을 한꺼번에 답합니다(다섯 마리 무리 중 평균 3.8). 나머지 둘이 암살자의 환상입니다 — **급소**(갑옷을 지나가는 한 방)와 **어둠 되감기**(싸움 중에 깨어 있던 것들이 너를 놓친다). 되감기가 이 직업의 고리를 닫습니다: 자취를 지우면 다음 한 대가 기습이 되고, 기습은 그림자를 갚습니다.

**마법사의 잔향.** 예전 특성은 "넷째 주문이 공짜로 두 번"이었는데, 할인은 축이 아닙니다 — 원래 쓰던 주문을 조금 더 자주 쓰게 할 뿐입니다. 지금은 주문마다 다른 잔향이 네 턴 남고, 다음 주문 하나가 그것에 따라 변합니다.

| 남긴 주문 | 잔향 | 다음 주문이 |
|---|---|---|
| 마력 화살 | 불씨 | 위력 +60% |
| 점멸 | 자취 | 턴을 쓰지 않는다 |
| 생명 탐지 | 눈 | 보이는 나머지 전부에게도 절반 |
| 서리 폭발 | 서리 | 맞은 것이 한 턴을 잃는다 |
| 지형 파악 | 지형 | 층 전체를 방으로 삼는다 |

마나는 한 글자도 안 건드렸습니다. 버튼도 안 늘었습니다. 다섯 단어가 스물다섯 문장이 됐을 뿐입니다.

**전사의 연타.** 버티기(네 턴 버티고 되받기)를 걷어냈습니다. 세기가 아니라 동사가 문제였습니다 — 측정하면 lv12 전사가 판당 10.7번 눌렀고 나머지 세 기예를 합친 것보다 많았습니다. 언제나 쓸 수 있고 한 번도 틀리지 않는 버튼이 가장 많이 눌리는데, 이 게임의 다른 모든 동사는 "어디에 설 것인가"를 묻습니다. 연타는 같은 슬롯을 앞으로 씁니다: 한 호흡에 넷까지, 맞을 때마다 다음 한 대가 35%씩 무거워지고, **빗나가면 거기서 끝**입니다.

**팔라딘의 맹세.** 사제와 주문 다섯 개를 **전부** 나눠 쓰고 있었습니다(`5/5`). 목록을 남에게 빌린 마지막 직업이었고, 사제 쪽은 축(응답 = 지고 있을 때 더 아문다)이 곧 회복 주문책이라 뗄 수 없으니 팔라딘 쪽을 뗐습니다.

맹세는 원래 방어 수치였습니다 — 맞을 때마다 +1, 최대 +8. 이제 그것이 **탄약**이기도 합니다. 태울 때마다 방어가 그만큼 내려가므로, 이 직업의 질문은 언제나 하나입니다: **아직 더 맞아도 되는가.** 도적의 그림자와 같은 문법이지만 모으는 방법이 정반대라 겹치지 않습니다 — 도적은 안 들켜야 모으고 팔라딘은 맞아야 모읍니다.

**속죄**(최대 셋, 견딘 만큼 아문다) · **선언**(2, 보이는 것을 두 칸 끌어온다) · **심판의 고리**(3, 둘러싼 것을 한 바퀴에) · **응보**(전부, 많이 맞았을수록 무겁다). 느린 직업이 궁수를 쫓아갈 수는 없으니, 선언은 **오게 만듭니다** — 대신 자는 것까지 전부 깨우는 것이 값입니다.

이 넷의 순서와 값은 전부 측정으로 정했습니다. 처음엔 응보를 1레벨, 속죄를 11레벨에 놓았는데 **2.4층에서 1.3층으로 떨어졌습니다** — 주문책을 뺏으면서 이 직업의 유일한 회복도 같이 뺏었고, 11레벨은 봇이 절대 못 가는 곳입니다. 속죄를 1레벨로 올리고, 회복량을 「바닥 + 맹세당 기울기」로 바꿔 맹세 하나로도 쓸 수 있게 했습니다.

그리고 처치할 때 맹세가 하나 풀리던 규칙을 없앴습니다. 벽이기만 할 때는 옳았지만(이길수록 벽이 낮아진다), 기예 넷이 같은 것을 태우게 된 지금은 같은 자원에 세금을 두 번 매기는 것이었습니다 — 측정하면 맹세가 **턴의 55%를 0으로 보냈고 25판에서 한 번도 안 찼습니다.** 대신 처치할 때 **들고 있는 맹세에 비례해 아뭅니다.** 벽을 많이 지고 있는 자가 가장 많이 아뭅니다.

### 진짜 이음매는 거리가 아니라 무리였다

"전사는 궁수에게 답이 없다"는 걱정으로 시작했는데, 격리해서 재 보니 **틀린 걱정**이었습니다. 같은 방·같은 레벨에서 궁수 하나를 붙여 보면 여섯 직업이 전부 40/40으로 이깁니다. 전사는 8턴에 체력 7%만 쓰고 끝냅니다. 한 마리짜리 원거리는 이 게임에서 위협이 아닙니다.

무리 넷을 붙이면 완전히 다른 표가 나옵니다.

| 직업 | 궁수 하나 (이김/죽음, 체력손실) | 무리 넷 |
|---|---|---|
| 사제 | 40/0 · 3% | **40/0** · 25% |
| 전사 | 40/0 · 7% | 39/1 · 49% |
| 마법사 | 40/0 · 4% | 31/9 · 60% |
| 팔라딘 | 40/0 · 19% | 26/14 · 62% |
| 도적 | 40/0 · 15% | 21/19 · 82% |
| 레인저 | 40/0 · 3% | **13/27** · 95% |

레인저는 처음 쟀을 때 **0/40**이었습니다. 무리전 로그를 읽으면 이유가 한 줄로 나옵니다 — 빗발 한 번, 덫 한 번, 그리고 **활로 13.8번 후려칩니다.** 간격이 지워지면 이 직업에는 아무것도 안 남습니다.

두 가지를 고쳤습니다. **덫 놓기가 이제 묻고 물러섭니다** — 이 기예의 주석은 원래부터 "따라오는 것을 땅이 잡게 한다"였는데, 정작 자기 덫 위에 서 있게 만들어서 넷이 둘러싼 상황에서는 아무 일도 안 했습니다. 그리고 **빗발이 3레벨짜리 기예보다 나빴습니다** — 기력 5 + 화살 3으로 각자에게 절반, 휩쓸기는 기력 3으로 인접 전부에게 0.8. 12레벨 마무리 기예가 3레벨 기예에게 지는 것은 밸런스 문제가 아니라 오래 산 오타입니다. 0.65로 올리고 기력 3으로 내렸습니다.

그래도 13/40이었습니다. 그래서 특성을 의심하고 **표적을 재 봤는데, 한 마리를 상대로도 0.00/5였습니다.** 무리 문제가 아니었습니다.

`표적`은 `swing()` 안에 조각 둘로 흩어져 있었습니다 — 누적 카운터가 한 분기에, 배율이 여든 줄 아래에. 화살을 쏘는 `loose()`는 **둘 다 안 건드렸습니다.** 즉 활이 곧 직업인 클래스가, 활을 곤봉처럼 휘두를 때만 자기 특성을 쌓고 있었습니다. HUD의 게이지는 영원히 0이었고 툴팁이 약속한 45%는 존재하지 않았습니다.

한 곳으로 모으고 화살에도 걸리게 하자 격리 측정에서 **최대 단계 ×1.43**(약속 ×1.45)이 나왔고, 무리전은 13/40 → **17/40**이 됐습니다. 여전히 여섯 중 꼴찌지만, 둘러싸이면 가장 약한 것은 이 직업의 정의이기도 합니다.

레인저는 세 번 고쳤습니다 — 행이 거짓말하던 것(1차 커밋), 덫과 빗발(2차), 그리고 특성 자체. 세 번 다 「없는 기능」이었지 「약한 기능」이 아니었습니다.

### 이 숫자들을 어떻게 냈는가

헤드리스 봇 하나로 여섯 직업을 같은 시드로 돌립니다. 이번에 배운 것 셋을 적어 둡니다 — 전부 **게임이 아니라 측정 도구가 틀렸던** 경우입니다.

- **턴이 안 가는 것을 버그로 읽지 말 것.** 이 게임의 동사 절반은 정당하게 턴 없이 반환합니다(오타 입력, 발밑에서 열리는 화면). "턴이 갈 때까지" 도는 봇은 설계를 멈춤으로 오해합니다. 봇은 **행동** 단위로 돌고, 모든 행동을 기록해서 멈추면 *어떤 동사*를 반복했는지 말합니다.
- **판은 서로 독립이어야 한다.** `meta.js`의 기록은 모듈 캐시에 쌓이고, 그게 다음 판의 **기억**(금화 +300, 시작 장비 +2, 물약 식별)이 됩니다. 40판 묶음의 마지막 판은 첫 판보다 부자로 시작합니다. 같은 코드의 도적이 여섯 직업 묶음에서는 2.2층, 혼자 돌면 2.48층이었습니다. 판마다 `Meta.forget()`을 부릅니다.
- **차이가 잡음보다 큰지 먼저 확인할 것.** 같은 코드로 시드 블록을 바꿔 40판씩 다섯 번 돌리면 표준편차가 0.06~0.09층입니다. 그보다 작은 차이는 발견이 아닙니다.

그리고 봇은 여섯 직업 전부 평균 **lv3.8~5.4**에서 죽습니다. 즉 3단(lv7~9)·4단(lv11~13) 기예와 주문은 어느 직업도 0~3%만 도달합니다. 사다리가 가파른 것인지 봇이 약한 것인지 알 수 없으므로 **사다리는 건드리지 않았고**, 대신 깊은 곳에서 시작하는 두 번째 자를 만들었습니다.

40판씩, 같은 봇, 같은 시드, 판마다 기록 초기화:

| 직업 | 변경 전 | 변경 후 | |
|---|---|---|---|
| 전사 | 2.1층 | 2.3층 | 봇에게 밀쳐내기를 가르친 몫이 큼 |
| 마법사 | 3.0층 | 3.2층 | |
| 사제 | 2.0층 | 2.0층 | 안 건드림 — 대조군 |
| 도적 | 2.7층 | 2.5층 | 마법사 주문책 다섯을 통째로 뺐음 |
| 레인저 | **40판 전부 스핀** | 2.8층 | 특성이 아예 안 걸리고 있었음 |
| 팔라딘 | 2.4층 | 2.5층 | 아래 참고 |

사제 하나만 손대지 않았고, 그 숫자가 소수점까지 같은 것이 이 표를 믿을 수 있는 이유입니다. 같은 코드로 시드 블록을 바꿔 재면 표준편차가 0.08층이므로, 0.2층보다 작은 차이는 발견이 아닙니다.

팔라딘은 주문책을 뺏긴 직후 1.9층까지 내려갔다가 2.5층으로 돌아왔습니다. 되돌린 것은 기예 수치가 아니라 **능력치 배분**이었습니다.

`CLASS_BAND`에서 팔라딘의 최고 능력치는 **매력**이었습니다. 갑옷 입은 사제이던 시절에는 말이 됩니다 — 지혜가 주문을 사고 매력이 값을 깎았으니까요. 주문책을 뗀 뒤 그 배분이 남긴 것은, **최고 능력치가 상점 흥정인 근접 직업**이었습니다. 측정하면 2레벨 팔라딘의 한 턴 기대 피해가 1.6, 전사가 4.6이었습니다. 힘 11.8 대 14.8, 명중치 2.2 대 6.3 — 판금을 입고 사제만큼 때리고 있었습니다.

힘을 prime으로, 매력을 good으로 내렸습니다. 기예도 몬스터도 한 줄 안 건드렸는데 **2.5층 · 무리전 26/40 → 36/40**이 됐습니다.

그리고 `CLASSES`에 있던 직업별 능력치 수정치(`mod`)를 지웠습니다. `createHero`가 그걸 읽는 것을 오래전에 그만뒀는데도 데이터에 남아 「팔라딘 힘 +2」라고 적혀 있었고, 실제로 굴러 나오는 값은 힘 11.8이었습니다. **읽히지 않는 데이터는 조용히 거짓말을 합니다.** 능력치는 이제 `CLASS_BAND` 한 곳에만 삽니다.

레인저 40판이 전부 멈춰 있었습니다. `spellSlots()`가 "붙어야 하는 기예"만 보고 버튼을 껐던 탓에, 활이 없거나 사선이 막혀도 **조준 사격이 켜져 보였습니다.** 누르면 `useArt`가 거절하고, 거절은 턴을 쓰지 않습니다. 봇은 판당 조준 사격을 301.6번 눌렀습니다. 행이 `useArt`와 똑같은 조건을 보게 고쳤습니다 — 행이 거짓말을 하면 사람도 봇과 같은 자리에 갇힙니다.

lv12·6층에서 시작해 기예 넷이 다 열린 상태로 30판:

| 직업 | 변경 전 | 변경 후 |
|---|---|---|
| 전사 | 6.1층 · 버티기×10.7 | 6.1층 · 연타×10.2 |
| 마법사 | 6.3층 · 화살×29.7 | 6.6층 · 화살+불씨×31.8 |
| 도적 | 6.4층 · **마력 화살×31.1** | 6.1층 · 도약×5.4 급소×3.1 되감기×1.0 부채×0.9 |

도적이 0.3층 얕아진 것은 남의 주문책을 뺏었으니 당연하고, 중요한 것은 오른쪽 칸에 **자기 이름의 동사 넷**이 들어왔다는 것입니다.

### 열다섯 층, 그리고 층마다 다른 성격

25층은 너무 길었습니다. 15층으로 줄이고 몬스터·장비의 등장 깊이를 전부 같이 당겼습니다(×0.6). 경험치 곡선도 `10·lv^1.78`로 낮췄습니다 — 층이 줄면 싸울 기회도 주니까요.

그리고 열다섯 층이 똑같이 생성되면 그건 같은 층이 열다섯 개입니다. 층마다 성격을 뽑습니다.

| 성격 | 방 개수 | 밝은 방 | 물 |
|---|---|---|---|
| 보통 | 11.8 | 5.0 | 10칸 |
| 좁은 굴 | 18.4 | 5.8 | 3칸 |
| 큰 방 | 5.6 | 3.4 | 9칸 |
| 빛이 없는 층 | 10.4 | **0.9** | 5칸 |
| 물에 잠긴 층 | 10.4 | 4.5 | **53칸** |
| 소굴 | 10.1 | 2.9 | 9칸 (거미줄 2배, 몬스터 1.35배) |

물은 은신을 죽이고 어둠은 시야를 죽이니, 이미 있던 규칙들이 층 성격과 맞물립니다. 입장하면 무슨 층인지 알려 줍니다.

### 미확인 물약과 두루마리

물약과 두루마리의 **외형이 판마다 뒤섞입니다.** "맑은 물약"이 이번 판엔 치유약이고 다음 판엔 독입니다. 판별하는 방법은 **써 보는 것뿐**입니다.

바닥에서만 나오는 여섯 가지를 새로 넣었습니다 — 격노(피해 +60%)·무쇠(방어 +10)·제련(장비 +1)은 좋고, 독·혼탁(실명)·저주는 나쁩니다. 상점은 이름 모르는 물건을 팔지 않으므로 이것들은 주워서 마셔 봐야 압니다.

이게 이 게임이 살 수 있는 **가장 싼 운**입니다. 조작이 늘지 않고, 매 판 스스로 새로워집니다.

### 보이게 만들기

두 번째 플레이 평은 *도파민이 없다, 선택이 고민되지 않는다, 매력적인 게 매력적으로 안 보인다, 운이 없다, 구덩이로 너무 자주 떨어진다* 였습니다. 앞의 셋은 시스템 문제가 아니라 **연출 문제**였습니다 — 목록 속 숫자는 도파민을 만들지 못합니다.

**등급.** 평범(흰색) · 마법(파랑) · 희귀(금색) · 유물(보라), 저주는 붉게. 이름 색이 배낭·상점·모닥불에서 전부 같습니다. 그리고 바닥에 떨어진 마법 이상의 물건은 **빛기둥**을 세웁니다 — 이름을 읽기 전에 좋은 것이 있다는 걸 먼저 봅니다. 희귀 이상은 한 번 본 자리면 어둠 속에서도 계속 보입니다.

처음엔 유물 기준을 7점으로 잡았는데 드롭으로는 도달이 불가능했습니다. 제일 좋아 보이는 등급이 이론에만 있었던 셈이라, 기준을 6점으로 내리고 정예 드롭이 45% 확률로 +1~+2를 달고 나오게 했습니다. 전체 드롭의 2%가 유물입니다.

**제단.** 2층부터 약 30%의 층. 피(체력 40%) · 금화(절반) · 장비(착용 중 하나) 중 하나를 바치면 대성공/성공/허탕/재앙이 나옵니다. 핵심은 **고르기 전에 확률을 막대로 보여준다**는 것입니다 — 값을 매길 수 없는 도박은 결정이 아니라 그냥 놀람이니까요. 장비를 바치면 대성공이 30%로 가장 높고, 피는 재앙이 12%로 가장 높습니다. 대성공에는 **능력치 영구 +1**이 들어 있습니다.

**구덩이.** 함정 다섯 중 하나였고 밟을 때마다 층을 통째로 건너뛰었습니다. 가중치를 줘서 전체의 5%로 줄이고, **민첩으로 가장자리를 붙잡게** 했습니다 — 민첩 높은 도적 90%, 둔한 전사 40%. 층을 잃는 건 이제 운이 나쁠 때의 일입니다.

### 재료 — 이 게임에 없던 순환

한 판 해 보고 돌아온 평이 정확했습니다. *너무 쉽고, 골드 쓸 데가 없고, 선형으로 강해지기만 하고, 장비는 쓸데없이 떨어진다.* 넷이 사실 한 문제였습니다 — **소비되는 것이 아무것도 없었습니다.** 금화는 쌓이고, 드롭은 쌓이고, 강화는 공짜라 힘이 일방적으로 올랐습니다.

이제 **잡템이 화폐**입니다.

- **분해** — 배낭의 무기·갑옷을 부숴 재료로. 등급·강화수치·속성 수에 비례합니다
- **쇳조각**(강화) · **마력 가루**(인챈트) · **정수**(재련) 세 가지
- **강화가 유료**가 됐습니다. +1은 50금+쇳3, +5는 410금+쇳15
- **재련** — 정수로 속성을 다시 굴립니다. 저주는 절대 붙지 않고, **저주가 있으면 그것부터 지웁니다**. 인챈트 도박의 안전망입니다

핵심은 **같은 장비를 팔면 금화, 부수면 재료**라는 것입니다. 둘 다는 안 됩니다. 이제 드롭 하나하나가 질문입니다.

### 떠돌이 상인

2층부터 약 30%의 층에 나타납니다. 소모품과 **재료**를 팔고 잡템을 삽니다. 마을은 한 번 내려가면 사실상 못 돌아가는 곳이라, 금화가 의미를 갖는 유일한 통로입니다. 층에 들어서면 지도에 미리 표시되므로 "이 층엔 상인이 있다"가 그 층을 다르게 만듭니다.

### 모닥불 — 한 번의 선택

층마다(약 60%) 모닥불이 하나 있습니다. 입장하면 지도에 미리 표시되지만, **입구 방과 계단 방에는 놓이지 않습니다** — 찾아가야 합니다.

셋 중 **하나만** 고를 수 있고 고르면 꺼집니다.

- **휴식** — 최대 체력 30% · 마나 전부 · 모든 상태이상 해제. 안전하고 남는 게 없습니다
- **강화** — 장비 +1 또는 주문 연마. 작지만 확실하고 영구적. **+5 상한**
- **인챈트** — 무작위 접두/접미. **다섯에 하나는 저주**고 이미 붙은 성질을 밀어낼 수 있습니다

이게 결정이 되는 이유는 **체력이 가득할 때 휴식이 무가치하고, 20%일 때 강화가 자살이기 때문**입니다. 셋의 가치가 상황에 따라 뒤집히지 않으면 그냥 메뉴일 뿐입니다.

처음 구현했을 때 모닥불이 모든 층에 있고 회복이 38%였습니다. 봇이 층마다 공짜로 회복하며 18.8층까지 내려갔고, 이 프로젝트에서 맨 처음 지적했던 문제 — *휴식이 공짜라 소모전이 성립하지 않는다* — 를 제 손으로 다시 만들어 놓은 셈이었습니다. 빈도 60%, 회복 30%, 강화 상한 +5로 내렸습니다.

### 마을

가게마다 **팻말**이 걸려 있고 그 아래 **상인**이 서 있습니다. 팻말에는 그 가게의 대표 품목 스프라이트가 그려지므로, 들어가 보지 않아도 무엇을 파는지 압니다. 상인은 여섯 명이 각기 다른 색으로 구워집니다 — 영웅의 직업별 색과 같은 `C` 채널 치환 방식입니다.

사고파는 데는 확인을 받습니다. 브라우저의 `confirm()` 대신 게임 서체로 된 모달을 씁니다 — 네이티브 대화상자는 렌더 루프를 멈추고 보안 경고처럼 보이는데, "이 검을 살까"에는 맞지 않는 어조입니다. `Y`/`Enter`가 예, `N`/`Esc`가 아니오. 속성이 붙은 물건을 팔 때는 되돌릴 수 없다고 따로 경고합니다.

### 세이브

슬롯 셋, `localStorage`. 타이틀의 **새 게임**은 어느 슬롯에 넣을지 묻고, **이어하기**는 어느 슬롯을 이어갈지 묻습니다. 이미 찬 슬롯을 덮어쓸 때는 확인을 받습니다 — 20층짜리 판을 말없이 먹는 로그라이크는 나쁜 로그라이크입니다.

저장은 **층을 옮길 때마다, 그리고 40턴마다** 자동으로 일어납니다. 별도의 저장 버튼은 없습니다.

**죽으면 슬롯이 비워집니다.** 퍼머데스는 그대로입니다. 이 처리는 종료 화면이 아니라 프레임 루프에 있습니다 — 함정으로도, 독으로도, 자동 이동 중 몬스터에게도 죽을 수 있는데 그중 하나라도 놓치면 세이브 스커밍이 되기 때문입니다.

까다로운 부분은 레벨의 TypedArray 넷과 Map 둘이었습니다. `Uint8Array`를 JSON에 넣으면 2640개의 번호 키를 가진 객체가 되므로 **base64로 내보냅니다** — 한 판에 약 19 KB입니다. 복원할 때는 `Object.create(Level.prototype)`으로 인스턴스를 만듭니다. 생성자를 부르면 복원하려던 던전을 버리고 새 던전을 만들어 버리기 때문입니다.

`game.js`는 여전히 `localStorage`를 모릅니다. 저장 시점을 잡는 것도 `ui.js`의 프레임 루프입니다 — 그 경계가 헤드리스 시뮬레이션을 계속 돌아가게 하는 것이라서요.

### 조작

한 번 두드려 한 칸이 아닙니다.

- **D-pad를 누르고 있으면** 그 방향으로 계속 걷습니다 (첫 반복 190ms → 62ms로 가속).
- **지도를 스와이프한 채 유지하면** 손가락 방향으로 계속 걷고, 손가락을 돌리면 방향이 따라옵니다.
- **가본 곳을 탭하면** BFS로 경로를 찾아 거기까지 걸어갑니다.
- **가운데를 누르고 있으면** 제자리에서 쉽니다.

전부 같은 규칙으로 멈춥니다 — **피격 · 새 몬스터 발견 · 아이템 습득 · 층 변경**. 판정은 직전 스냅샷과 비교하므로, 내 걸음이 만든 변화든 바깥에서 벌어진 변화든 똑같이 잡힙니다.

### 조명

이 게임의 시각적 중심입니다. 시야는 보이냐/안 보이냐의 이진값이 아니라, 등불로부터의 거리에 따라 타일 알파가 연속 감쇠합니다. 밝은 방에 들어서면 방 전체가 드러나고, 어두운 복도에서는 등불 반경까지만 보이며, 지나온 자리는 어둡게 기억으로 남습니다. 횃불이 꺼지면 반경이 7 → 2로 줄어듭니다.

## 밸런스 검증

`game.js`가 DOM에 의존하지 않으므로 Node에서 그대로 돌릴 수 있습니다. 개발 중 다음을 확인했습니다.

- 48개 종족×직업 조합 전부 정상 생성
- 25개 층 × 20회 = 500회 생성에서 도달 불가능한 계단 0건
- 층을 정리하며 내려가는 봇: 평균 22.6층 도달, 승률 4/10
- 계단만 찾아 다이빙하는 봇: 9~14층에서 전멸

다이빙과 정리 플레이의 결과가 확실히 갈리도록 맞춘 수치입니다. 조정은 `game.js`의 `playerAttack`/`monsterTurn` 명중식과 `data.js`의 `xpToLevel`을 보시면 됩니다.

치명타·연격·기습을 넣은 뒤 같은 봇으로 변경 전후를 나란히 돌려 확인했습니다. 도달 깊이는 거의 그대로고 (정리형 9.5층 → 9.8층), 대신 레벨이 12.2 → 15.6으로 올랐습니다. 처치 속도는 빨라졌지만 깊이가 그만큼 되받아치기 때문에 난이도 곡선은 유지됩니다.

몬스터 행동·특수 타일·미믹까지 넣은 뒤에는 정리형이 7.4층으로 내려갔습니다 (원본 9.5층 대비 약 22% 어려움). 봇은 그 단계에서 추가된 대응 수단을 하나도 쓰지 않습니다 — 문을 닫지 않고, 궁수에게서 물러나지 않고, 상자를 미믹인지 보지도 않고 전부 엽니다.

속성·강화·모닥불까지 얹었을 때는 정리형 20.5층 / 다이빙형 15.0층이었는데, 이건 **너무 쉬웠습니다.** 강화가 공짜라 힘이 제동 없이 올랐기 때문입니다. 재료 경제를 넣은 뒤 **정리형 16.0층(1승) / 다이빙형 12.9층**이 됐고, 판당 분해 17.8회 · 상인 방문 3.9회로 순환이 실제로 돕니다.

이전 측정은 참고로 남깁니다 — **정리형 20.5층 / 다이빙형 15.0층**.

15층으로 줄이고 층 성격과 미확인 물약까지 넣은 뒤: **정리형 10.6/15층에 승률 4/12, 다이빙형 8.0/15층.** 봇이 처음으로 대군주를 잡았습니다. 원본보다 관대해진 것은 성장 수단이 생겼으니 당연하고, 중요한 건 **정리가 다이빙을 다시 앞질렀다는 것**입니다 — 원래 이 게임이 노렸던 구도입니다. 봇에게 모닥불을 찾아가는 행동을 가르치자 도달 깊이가 8.4층에서 14.7층으로 뛰었는데, 그 차이가 곧 이 시스템의 무게입니다.

여전히 **승률은 0에 가깝습니다.** 25층의 대군주(700hp/46atk/AC30)가 벽으로 남아 있습니다. 봇은 상점을 쓰지 않고 주문을 쓰지 않고 모닥불에서 절대 도박하지 않으므로, 이 숫자들은 바닥이지 천장이 아닙니다. **최종 조율은 사람 손으로 해야 합니다.**

봇 밸런싱 과정에서 실제 버그 두 개가 잡혔습니다. 함정을 맵 전체에서 균일 추출하는 바람에 시도의 대부분이 암반에 떨어져 **한 층에 함정이 0개인 경우가 많았고**, 잠긴 문 하나가 계단으로 가는 유일한 통로를 막아 **봇이 턴 상한까지 헤매는 층**이 생겼습니다.

조작과 연출은 `game.js` 밖에 있어서 헤드리스로는 검증되지 않습니다. 그쪽은 Playwright로 실제 페이지를 띄워 확인했습니다.

- 홀드 1회 입력 → 13턴, 7칸 떨어진 타일 탭 → 정확히 7턴 만에 도착, 이동 중 적 등장 → 즉시 0턴 정지
- 문: 부딪쳐 열림 → 통과 → 버튼 노출 → `c`로 닫힘
- **닫힌 문 너머가 실제로 보이지 않는지** (밝은 방은 벽과 무관하게 방 전체를 드러내므로, 방을 어둡게 만든 뒤 측정)
- 잠긴 문을 거치지 않고 계단에 도달 가능한지
- 미믹이 먼저 물고 그 다음 내 공격이 들어가는지, 함정 상자가 함정을 터뜨린 뒤 전리품을 주는지
- 종족 면역 7가지 조합 전부 (드워프/실명, 노움/마비, 엘프·하프트롤/공포 저항 + 인간 대조군 3건)
- 공포가 명중을 55%로, 실명이 시야를 7 → 1로 실제로 바꾸는지
