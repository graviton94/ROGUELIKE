# 도트 스타일 — 배운 것

에셋을 쓰지 않는다. **규칙만 가져온다.**

`study.py`가 0x72 DungeonTileset II (CC0)를 픽셀 단위로 세어 뽑아낸 값입니다.
PIL이 없어 PNG를 직접 풀었습니다 (zlib + 언필터).

```
불투명 픽셀 62,108 · 고유 색 56개
가장 많이 쓰인 색  #222222  35.50%      ← 공용 외곽선 한 색. 순검정이 아니다.
                  #483b3a  10.84%      ← 그늘
                  #fdf7ed   4.83%      ← 하이라이트
외곽(투명에 닿은 픽셀) 평균 명도 39 / 내부 124  → 외곽이 85 어둡다
   외곽 픽셀 중 V<64 비율 94%
16×16 칸 401개 · 한 칸이 쓰는 색: 최저 3 · 중앙값 5 · 최고 10
명도 분포  V10–20 36%  ·  V80–100 21%   ← 중간대가 얇다 = 대비가 세다
채도 분포  S<20 55%                      ← 대부분 저채도, 고채도는 강조에만
칸 위 절반 114 / 아래 절반 107           ← 광원은 위
```

## 그래서 규칙 여섯

1. **공용 외곽선 한 색.** 순검정이 아니라 색이 든 짙은 색 (`#151120`). 전부 두른다.
2. **한 칸은 5색 안팎.** 램프는 4단 — 그늘 · 본색 · 밝음 · 하이라이트.
3. **램프를 따라 색조를 민다.** 원본은 H4 → H12 → H24 → H37로 흘렀다.
   어두울수록 붉게/차갑게, 밝을수록 노랗게.
4. **화면 대부분은 저채도.** 고채도는 강조 두셋에만 쓴다.
   (이전 시안이 진흙처럼 보인 이유가 정확히 이것이었다 — 전부 고채도였다.)
5. **대비를 세게.** 중간 명도에 몰지 않는다.
6. **광원은 위.** 윗면이 밝고 아랫면이 어둡다. 예외는 스스로 빛나는 것(화로).

`repaint.py`가 이 규칙대로 스프라이트를 다시 칠하고, 칠하기 전에 검증합니다 —
모든 칸이 16행 × 16자인가, 팔레트 밖 문자가 없는가. (첫 시도에서 오타 13건을 잡았다.)

## 그림보다 중요한 것

**저해상도로 그리고 정수 배율로 확대한다.** 8비트로 보이게 만드는 건 이 결정 하나다.
`fit()`이 화면에 맞춰 배율을 정수로만 고르고, 스프라이트·HUD·글자까지 전부
그 저해상도 캔버스 안에서 그린다. 그 위에 주사선과 비네트를 얹는다.

그리고 실시간 전투에서는 그림보다 **이펙트가 화면을 판다** — 히트스톱, 화면 진동,
넉백, 충격파 고리, 파티클, 피해 숫자, 피격 섬광, 그리고 압력이 차오를수록
밝아지는 발밑의 등불.
